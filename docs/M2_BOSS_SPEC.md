# M2 删名者Boss机制协议

> 适用版本：v0.8-chapter-complete
>
> 第一交付：两阶段Boss机制垂直切片、终结选择与最小章节结算。

本协议以 `design/DEMO_CONTENT_V0.1.md` 第八节为权威内容来源，补足工程字段、触发顺序与可读性约束。

---

## 一、核心原则

1. 删除是**战斗内可逆修正**，不修改RunModel中的永久牌组实例。
2. 被删信息必须始终可见：显示原值、当前值、删除来源与恢复方式。
3. 删除不得产生非法卡牌：费用不小于0，失去类别时仍可正常打出，关键词删除只禁关键词附加效果。
4. 阶段转换必须等待当前卡牌及完整效果队列结算完毕。
5. 固定种子下，费用篡改和关键词目标选择完全复现。
6. UI只展示规则状态与派发选择，不持有删除状态。

---

## 二、Boss状态

在CombatModel中维护Boss专属状态对象或等价typed字段：

```gdscript
boss_phase: int                  # 1校对 / 2除名 / 3终结
boss_transition_pending: bool
boss_terminal_choice_pending: bool
boss_recovery_count: int
boss_strength: int
boss_cost_edits: Dictionary      # instance_id -> 原费用/增加值
boss_deleted_types: Dictionary   # instance_id -> 原类别
boss_deleted_keywords: Dictionary# instance_id -> 被禁关键词集合
boss_type_sequence: Array[int]   # 本阶段连续类别，不重复时推进
boss_last_recovery_text: String
```

终结选择是否开放“读取被删原文”由 `boss_recovery_count >= 2` 决定。

---

## 三、第一阶段：校对（168～101生命）

意图循环：

1. 篡改费用：从抽牌堆+弃牌堆中按固定种子选2个不同实例，费用+1。
2. 红笔划除：8×2伤害。
3. 边注：2张删节洗入抽牌堆。
4. 校对完成：14格挡，下一次攻击+6。

### 费用显示

受影响牌显示：

```text
费用 2（原1，红笔+1）
```

`get_card_cost()`在基础费用、升级和缺名修正后再应用Boss费用修正，最后走RuleEngine裁剪。

### 恢复

玩家连续打出三种**不同正式类别**（攻式/守式/律式）后：

- 恢复一张最早被篡改牌；
- Boss失去最多6格挡；
- `boss_recovery_count += 1`；
- 类别序列清空，重新累计。

状态牌不参与；重复类别会从该类别重新开始序列。

---

## 四、阶段转换

Boss生命首次降到100或以下：

1. 当前卡牌及效果队列完整结算；
2. Boss格挡清零；
3. 清除所有费用篡改；
4. phase切到2；
5. 战斗日志与状态区显示：
   - `REC-10 / 可覆写载体`
   - `我删掉的不是你的名字。我删掉的是他们给你的用途。`

阶段转换不结束玩家回合，不额外抽牌。

---

## 五、第二阶段：除名（100～2生命）

意图循环：

1. 删除类别：标记“下次抽牌得到的第一张非状态牌”，它进入手牌时暂时失去类别。
2. 无主宣判：16伤害；玩家存在任意缺名时改为22。
3. 删除关键词：按固定种子从手牌选1张带关键词牌，禁用其所有关键词附加效果。
4. 返还原稿：清除全部缺名；每清除1层，Boss力量+3。

### 类别删除语义

- 卡牌仍可支付费用和打出；
- 基础伤害/格挡/抽牌照常；
- 不触发攻式/守式/律式相关连锁、记录、缺名消费或回响类别匹配；
- 显示`类别：已删除（原攻式）`。

### 关键词删除语义

第一版关键词集合：超载、封存、回响、消逝。

- 只禁用关键词对应附加效果；基础数值照常；
- 若卡牌只由关键词构成，仍允许打出但日志明确“基础正文为空”；
- 显示`关键词：回响（已删除）`等标记。

### 恢复

- 裂解触发：恢复最早一项关键词删除；
- 封存牌解封：恢复最早一项类别删除；
- 回响成功结算：Boss力量-1（最低0）。

每次实际恢复信息时`boss_recovery_count += 1`；无删除可恢复时不计数。

---

## 六、终结阶段（1生命）

Boss生命最低锁定为1，不再可选为伤害目标，战斗暂停并进入终结选择：

1. 交付定义律印：总是可选。
2. 读取被删原文：仅`boss_recovery_count >= 2`时可选；否则显示缺少条件。

两项都结束远征。第二项添加证据“第十份校准记录”，并在结算显示额外台词：弥拉把玩家称作“第十种答案”，随后改口为“第七名回收者”。

---

## 七、UI要求

战斗状态区新增Boss信息：阶段、REC-10档案、力量、恢复次数、当前被删信息。

卡牌按钮显示当前变更，不依赖tooltip：

- 费用变化；
- 类别删除；
- 关键词删除；
- 对应恢复提示。

Boss意图文本必须明确将删除什么及如何恢复。

终结选择使用响应式滚动页面与固定底部/操作区，不允许裁切。

---

## 八、验收测试

- 168生命、正确四步意图循环；
- 费用篡改只作用抽/弃牌堆2个不同实例，固定种子复现；
- 三类别恢复费用并削6格挡；
- 100生命阈值在卡牌完整结算后转换；
- 转阶段清费用和格挡；
- 删除类别不阻止打牌但禁类别连锁；
- 删除关键词保留基础数值并禁附加效果；
- 裂解/解封/回响恢复语义正确；
- 生命锁1且不可继续伤害；
- 两种终结选择条件与结算正确；
- 所有牌区不存在永久污染；
- 固定种子Boss模拟可复现且无超时。
