# 《断环》项目路线图

> 状态：Pre-Alpha 规则原型
>
> 当前基线：v0.7-expedition-skeleton（M1 已完成）
>
> 目标：一段可独立试玩、20～30分钟、从开局到Boss结算的“无字之城”Demo

本文件是项目的**路线与优先级真相源**。数值口径和协作规则见 `BALANCE_AND_CONTRIBUTING.md`；详细世界观和内容见 `../design/`。

---

## 一、产品目标

Demo需要证明四件事：

1. **核心战斗成立**：超载、封存、回响能形成不同构筑方向，而不是只有一种最优打法。
2. **远征选择成立**：路线、奖励、商店、锻造和事件会改变后续决策。
3. **碎片叙事成立**：玩家能从卡牌、敌人、事件和Boss中提出问题，并在结算时获得一次可回溯的小反转。
4. **工程基础成立**：固定种子可复现、存档可继续、测试与模拟能阻止规则回归。

### Demo完成定义

只有同时满足以下条件，才能称为“Demo完成”：

- 从标题页开始，不用开发者工具，完整走到Boss结算
- 一局目标时长20～30分钟
- 至少存在两种可辨识的构筑路线
- 有分叉路线、资源消费、牌组改变、事件与精英选择
- 删名者Boss至少两阶段，删除机制可读、可恢复、可反制
- 失败与重开正常，固定种子完整复现
- 存档/继续可用
- 其他玩家不看源码也能独立试玩
- 所有CI与数值阈值检查通过

```
M0 数值可信
```

## M0：数值可信（已完成，v0.6）

> 完成记录：12 个固定种子下，激进超载平均裂解 1.17；压力校勘体场景中激进超载胜率 41.7%、回响优先胜率 66.7%；四种策略形成不同指纹；倒读者平均 6.1 回合且最短 4 回合；全部逐局指纹可复现。

### 目标

让模拟真正覆盖游戏的风险收益，而不只是证明代码不崩。

### 工作项

1. 新增 `OVERLOAD_AGGRESSIVE` 模拟策略：
   - 优先使用越界读取、裂隙挥击
   - 不主动使用强制稳定
   - 不稳定≥8时优先临界许可
   - 不稳定≥5且可支付时考虑崩解协议
   - 生命低于25%才转防御
2. 增加高压敌人模拟配置：伤害较普通版本提高约40%～50%，用于压力测试，不直接进入主线。
3. 模拟新增指标：
   - 胜率 / 败率 / 超时率
   - 平均与P25/P50/P75回合数
   - 平均剩余生命
   - 裂解次数分布
   - 各卡牌使用频率
   - 遗物触发次数与净收益
4. 增加策略对照：保守、激进超载、封存优先、回响优先。
5. 调整倒读者，使其机制至少能完整执行2轮。

### 退出门槛

- 激进超载策略平均裂解次数≥1.0
- 至少一个高压场景胜率处于40%～80%，模拟中存在真实败局
- 同一场景不同策略的结果出现可解释差异
- 裂纹稳定器与无字藏书票的模拟指纹不再完全相同
- 倒读者平均战斗回合≥4
- 全部结果固定种子可复现

### 本阶段禁止

- 不增加地图内容
- 不做Boss
- 不接新遗物
- 不做美术动画

## M1：远征骨架（已完成，v0.7）

> 完成记录：9层固定结构、2/4/6层分叉、稳定节点ID与种子内容已落地；12个种子×2种路线共24局全部到达Boss占位。事件经济路线11/12可在第4层购买普通卡，5/12可负担首次移除；战斗路线不依赖高额事件时买不起遗物；24局共购买11张卡、支出424墨晶；锻造路线12/12完成实例升级。地图、库存、价格、实例ID与路线指纹均可复现。

### 目标

把孤立战斗串成具有路线代价、资源循环和牌组成长的最小远征。

### 先设计协议，再填内容

新增数据结构：

- `MapGraph`：节点、层级、连边、固定种子生成
- `MapNode`：战斗、精英、事件、商店、锻造、休整、Boss
- `RunState`：当前位置、已访问节点、生命、墨晶、牌组、遗物、证据
- `CardUpgradeCatalog`：每张牌的升级变化

### 工作顺序

1. 9层分叉地图的数据模型与固定种子生成
2. 路线选择UI（仍保持纯色、无动画）
3. 商店：买牌、移除牌、买遗物
4. 墨晶价格与来源/消耗闭环
5. 锻造：升级一张牌
6. 牌组查看、选择、移除和升级的统一UI
7. 把现有战斗、奖励和3个事件挂到地图节点协议

### 退出门槛

- 固定种子下地图、连边、节点内容完全复现
- 至少有两条合法路线通往Boss
- 路线选择会改变精英、事件、商店和锻造的可达性
- 墨晶既有来源又有合理消耗，不能无限积累
- 玩家至少能移除1张牌并升级1张牌
- 牌组实例标识在奖励、升级、移除、存档中保持稳定
- 从地图开局可一路走到Boss前节点

### M1暂不要求

- 不要求全部6个事件与8件遗物完成
- 不要求正式Boss完成
- 不要求美术地图

## M2：章节闭环（进行中：Boss垂直切片已完成）

> 当前完成：删名者168生命两阶段、费用/类别/关键词删除与恢复、REC-10转阶段、生命锁1终结选择、两种最小结算均已接入。8个固定种子Boss模拟8/8胜利、无超时，平均10.12回合、平均恢复2.25次，读取原文结局7/8可用。
>
> 尚未完成：剩余3个事件、8条线索来源完整接入、带来源的证据档案、已有证据改变Boss台词/选项，以及整局20～30分钟真人试玩验证。因此M2不能标记完成。

### 目标

完成“无字之城”从进入到删名者结算的整章体验。

### 工作项

1. 补齐剩余3个事件，使总数达到6
2. 把8条线索矩阵接入：
   - 卡牌风味文字
   - 敌人台词
   - 事件结果
   - 遗物描述
   - Boss阶段文本
3. 建立轻量证据档案：只显示已发现证据及来源，不自动替玩家推理
4. 实现删名者Boss垂直切片：
   - 第一阶段：篡改费用；三种不同类别连续打出可恢复
   - 第二阶段：删除类别与关键词；裂解、解封、回响可恢复或削弱
   - 所有变更必须可见、可预测、可撤销
5. 实现Boss终结选择与Demo结算
6. 让已有证据改变至少一个Boss台词或结算选项

### Boss实现策略

Boss不等全部系统“完美”后才动手，但必须等M1远征骨架稳定。先做一个最小两阶段切片验证“删除卡牌信息”是否可读、可反制，再扩写文本与数值。

### 退出门槛

- 固定种子下能从第1层完整走到Boss结算
- Boss两阶段都可稳定完成
- 删除机制不会让玩家无法判断费用、类型或合法操作
- 至少一个旧线索在结算时获得新解释
- 不新增设定也能支撑反转；玩家可回溯旧文本验证
- 一局目标时长20～30分钟

## M3：Demo硬化

### 目标

把“能完整跑”变成“可交给别人稳定试玩”。

### 工作项

1. 接线剩余6件遗物，总数达到8
2. 每件遗物加入数据定义、规则阶段、测试和模拟统计
3. 存档/继续：
   - 版本化存档schema
   - 固定种子、地图、牌组实例、遗物、证据、事件状态
   - 战斗外随时保存；战斗中按明确策略保存或禁止
4. 全内容数值模拟：
   - 多策略
   - 多路线
   - 全敌人/遗物/事件
   - 胜率、回合数、生命、牌组规模、墨晶流动
5. 中文文本审校、术语一致性、自动换行
6. 无障碍与操作：键盘、焦点、可取消选择、错误提示
7. 导出macOS/Windows试玩包
8. 添加崩溃恢复与兼容性检查

### 退出门槛

- 新玩家无需口头指导可完成一局
- 存档可跨重启恢复
- CI、全量模拟与导出冒烟全部通过
- 无阻断流程、无丢牌、无重复牌实例、无不可恢复选择状态
- README足以让其他开发者搭建与测试

## 五、范围控制

### Demo范围内

- 1名角色
- 19种卡牌
- 3普通敌人 + 1精英 + 1Boss（路径教学敌人属于序章引导）
- 8件遗物
- 6个事件
- 9层地图
- 1个商店、1个锻造节点类型
- 1段序章、1段结算

### 明确不进入本Demo

- 第二角色
- 第二纪元
- 真正无限程序生成
- 复杂卡牌分支升级树
- 完整推理板
- 在线功能
- 成就系统
- 模组系统
- 正式美术资产生产

任何新增想法必须先回答：它是否直接帮助四个产品目标？若否，进入后续候选，不插入当前路线。

## 六、风险登记

| 风险 | 当前迹象 | 缓解方案 |
| --- | --- | --- |
| 模拟失真 | M0 已出现真实败局与裂解，但策略仍非真人 | M1 后扩展多路线、多牌组样本 |
| 战斗过短 | 倒读者已校准到平均 6.1 回合；主线仍约2～3回合 | 保留主线友好度，按正式敌人逐个校准 |
| 牌组稀释 | 只增不减 | M1商店移除与锻造升级 |
| 经济无意义 | 墨晶无出口 | M1商店与价格模型 |
| Boss不可读 | 删除卡牌信息天然高风险 | M2先做垂直切片，可恢复、可预览 |
| 叙事像随机文本 | 事件已有但无回收 | M2证据来源+Boss回应+结算翻转 |
| 规则文件继续膨胀 | CombatModel曾过度集中 | 目录化、操作化、选择器化，不回退 |
| 存档返工 | schema尚未冻结 | M1稳定实例ID，M3再版本化存档 |

## 八、下一步唯一优先事项

**进入 M2 章节闭环，先做删名者Boss机制垂直切片，不并行接剩余遗物或美术。**

第一张任务单应是：

> 定义删名者的两阶段状态协议与“删除/恢复卡牌关键词、费用或类别”可逆修正模型，在机制测试场实现最小Boss垂直切片；所有被删信息必须可见、可预测、可恢复，并以自动测试验证不会产生非法卡牌或不可操作状态。

Boss机制成立后，再补齐剩余事件、证据档案、旧线索回应和Demo结算。
